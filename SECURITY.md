# Security policy

## Supported versions

Until the first stable release, security fixes are provided for the latest
published `0.1.x` version only.

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability. Use the repository’s
private GitHub Security Advisory reporting flow:

1. Open the repository’s **Security** tab.
2. Choose **Advisories**.
3. Select **Report a vulnerability**.

Include the affected version, reproduction steps, impact, and any suggested
mitigation. Maintainers will acknowledge a complete report as soon as
practical, coordinate a fix and release privately, and credit the reporter when
requested.

Never include real bearer tokens, OIDC assertions, refresh tokens, agent
prompts, or local usage files in a report. Replace them with synthetic fixtures.
